**Student:** what is the purpose of the exact solution function

**Claude:** It's an answer key for checking your simulation.

Your real model will eventually have microbes, nickel and isotopes, and no one can solve that exactly with a formula. The only way to get answers is to simulate: take many small steps forward in time. The simple case, with a steady volcanic source and burial and nothing else, has an exact formula:

```

```

So you can:

1. Run your simulation on that simple case.
2. Compare it to `exact_solution` at every time step.
3. If they match, your stepping code is right. Now you can trust it when you add the complicated parts that have no formula.

| | `exact_solution` | `simulate` |
| --- | --- | --- |

**Claude:** It's what actually runs the test.

The file defines `test_matches_exact_solution`, but defining a function doesn't run it. Without the block at the bottom, `python3 project/test_carbon.py` would define the function, do nothing, and print nothing. You couldn't tell whether the test passed.

```python
if __name__ == "__main__":
    biggest = test_matches_exact_solution()
    print(f"passed: largest difference is {biggest}")
```

1. It calls the test. If the `assert` fails, the program stops here with your error message.
2. If it gets past that line, the test passed, so it prints `passed` and the largest difference.

**Why the `if __name__ == "__main__":` line?** Python sets `__name__` to `"__main__"` only for the file you run directly. If another file imports this one, as you do with `import carbon`, `__name__` is the module's name instead, so the block is skipped. That means:

- Running `python3 project/test_carbon.py` runs the tests.
- Importing it from elsewhere just makes the test functions available, without running them.

It's the same idea as the block at the bottom of `main.py`. When you write more tests, call each one inside that block so a single command runs them all.
